# 两份代码与 PDF 数学结构的差异

对照文件：`D:\浏览器下载\Untitled (1).pdf` 第 3-8 页。

## PDF 与代码一致的主干

- 状态采用三维相对位置和相对速度；MPC 输出三维平移综合力。
- 模型一采用滚动基础力 `tau_base,k=tau[k-1]`，因此新作用量为 `tau[k]-tau[k-1]`。
- 融合版本包含模型二和逐轴非负、和为 1 的权重；模型一版本固定为纯模型一。
- PDF 代价包含位置、相对速度、综合力和综合力变化量；代码为保持模型一/融合版本的同一工程语义，将“综合力”项实现为候选模型的有效作用量。
- 都有力、力变化率、距离/视场约束，以及由位置测量估计速度的卡尔曼滤波。

## 动力学和离散化

1. PDF 手写推导从完整 Fossen 式出发，但随后只保留平移并线性化。代码进一步固定为 `M_t v_dot + D_L v = -u`，未实现科氏项、二次阻尼、恢复力、环境力、姿态耦合和旋转自由度。
2. PDF 的位置式是 `p[k+1]=p[k]+Ts*v_r[k+1]`。代码对联合的 `[p,v]` 连续系统做精确零阶保持离散化，所以位置输入项与该半隐式公式不完全相同；采样周期很小时两者接近。
3. PDF 同时给出精确 `F,G` 和欧拉近似。代码选择矩阵指数得到的精确零阶保持离散化。
4. 代码明确使用机体系 FRD `[前,右,下]`，并先将 PDF 前部的左相机光学系 `[右,下,前]` 转换到 FRD。PDF 的 MPC 部分没有把这一坐标转换写入公式。

## 双模型融合代码

1. PDF 的权重辨识使用多步相对位置预测误差 `e_ij`，并对预测步、历史时刻加权。融合代码现在保存历史起点，并用之后实际执行的力逐步推进两个模型；每个未来位置到达后都会回头评分，因此统计量与该结构一致。
2. 代码按三个轴分别估计权重，加入残差裁剪、`epsilon` 正则和最小权重裁剪。PDF 最终式建议了 `epsilon` 与裁剪，但这些工程参数的具体取值未给出。
3. MPC 预测时，代码在整个当前时域冻结刚估计出的逐轴权重；PDF 没有明确说明时域内未来权重如何演化。
4. PDF 的卡尔曼预测单独写成 `F v_r + G tau + w`，更像模型二。融合代码实际用两候选模型的加权均值推进滤波器均值，因此不等于 PDF 卡尔曼小节所写的预测式。

## 纯模型一代码

1. 纯模型一版本严格使用 `A_d x + B_d(tau-tau_previous)`，不计算模型二和权重。这与 PDF 的模型一段一致，但与 PDF 卡尔曼小节写出的 `G tau` 不一致；本实现选择让估计器与 MPC 的模型一假设一致。
2. 当前拍使用传入的上一拍“已实现综合力”；没有力观测器时用上一饱和命令近似。PDF 将 `tau[k-1]` 当成已知量，没有讨论命令力与实际力的偏差。
3. 纯模型一只对力增量响应。力一旦保持恒定，它只被当作新的匹配基础力，不会继续产生相对加速度。因此在力/变化率限幅和有限时域共同作用下，闭环可能停在非零位置误差；示例的 60 步仿真正显示了这一点。PDF 说模型一用于“匀速跟随”，但没有讨论它从较大初始位置误差重新捕获目标时的可达性和稳态偏差。

## 代价函数和约束

1. PDF 的 `R_tau` 惩罚绝对综合力。融合代码把它工程化为 `tau[k]-diag(a1)tau[k-1]`；纯模型一固定 `a1=1` 后，该项为 `tau[k]-tau[k-1]`，并与 `S_tau` 的平滑项叠加。这样不会把非零匹配力错误地压回零。
2. 代码在最后一个预测状态增加了终端权重倍数；PDF 的代价没有单独终端项。
3. 代码还对视场/距离松弛变量加入二次和线性惩罚，并限制松弛上界；PDF 只说“考虑采用”软约束，没有把松弛代价写入 `J`。
4. PDF 写的是欧氏距离 `d_min <= ||p|| <= d_max`。下界是非凸约束。代码改为前向距离分量的上下界，并软化两端，以保持凸 QP。
5. PDF 用相机坐标比值 `|x_c/z_c|`、`|y_c/z_c|` 表示视场。代码在相机与机体对齐、前向距离为正的假设下，将它改写成 FRD 中的线性锥边界，并把安全角直接从半视场角中相减。
6. 力和力变化率是硬约束；位置距离和视场是软约束。求解失败时代码还有限速回退策略，PDF 未定义该策略。

## 卡尔曼滤波、时延与控制分配

1. 代码实现标准位置量测更新，并用“白噪声加速度”构造过程协方差；PDF 只列出抽象过程噪声 `w_k`，没有给协方差离散化。
2. PDF 提到延时卡尔曼滤波，两个代码都没有实现测量时间戳回溯或延时补偿。
3. PDF 用通用六维广义力和 `C` 的伪逆分配 8 个推进器。代码使用 FineSUB 固件里的上下两组 4x3 混控矩阵、标定比例、符号、死区和逐电机饱和，不是通用 `C^dagger`。
4. MPC 仍只控制三轴平移；姿态力矩由外部姿态控制器负责。跟踪器默认分配时姿态输入为零，也没有加入 PDF 讨论的 `M_z` 视野控制。
5. 代码额外包含目标丢失回退、可选基础力慢适应、命令量化和两种下发路径；这些都不在 PDF 数学结构中。
