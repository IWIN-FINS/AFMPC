# 当前旋转代码与数学模型的逐项差异

核对对象：`Untitled (2).pdf`、此前“旋转加入尝试”对话中的补充推导，以及
`MPC_dual_model_yaw` 在 2026-08-14 合入当前实机平移改动后的代码。本文把差异分为四类：

- **严格不同**：公式、默认控制目标或算法含义不完全相同；
- **数学模型有、代码省略**：实机前应明确是否补上；
- **代码额外加入**：为可运行性、安全性或数值稳定性增加，不代表 PDF 推导错误；
- **仅实现形式不同**：数学含义基本一致，但符号、离散方式或参数化方式不同。

## 1. 已经严格对齐的核心部分

以下部分与 PDF 的旋转版主体一致，不属于差异：

1. 机体系采用 FRD：`x` 前、`y` 右、`z` 下；正 yaw、正 `omega`、正 `N`
   表示艏部向右转。
2. 相机位置先通过 `p_body = r_bc_body + R_bc p_camera` 转到机体系。
3. yaw 旋转采用有限角度矩阵 `Rz(-Delta psi)`，没有使用小角度近似。
4. 相对速度和位置按
   `v+ = R(Fv + G f_eff)`、`p+ = Rp + Ts v+` 递推。
5. yaw 增量使用 `Delta psi = Ts(omega+omega+)/2`。
6. 模型一以 `tau-tau_base` 为输入，模型二以 `tau-tau_h` 为输入；`tau_base` 只属于
   模型一，`tau_h=h(0)` 只属于 Fossen 目标静止分支。
7. 融合权重逐轴形成对角矩阵，并在一次 QP 内冻结。
8. 增广状态是 `x=[e,v,tau_previous]`，其中 `e=p-p_d`；代码中的
   `A_j/B_j/d_j` 与 PDF 给出的旋转 LTV 递推一致。
9. QP 只优化三轴平移力增量，yaw 轨迹在 QP 外生成并冻结。
10. 绝对力、力增量以及软视场约束均以线性约束进入 QP，只执行第一步控制量。
11. 历史评价采用当前实验平移融合配置的二维阶梯掩码：窗口为 `8`，预测区间为 `5`，
    `H_cap=[5,5,5,5,5,4,3,1]`、`omega_h=[1,1,1,1,1]`，`h=0` 不计分，启用格子的
    权重重新归一化。
12. 历史模型回放使用实际执行力和实际 IMU yaw 增量，而不是当前 QP 的名义预测量。

## 2. 模型范围、坐标和采样方面的差异

1. **数学模型有、代码省略**：PDF 从完整六自由度 Fossen 方程
   `M nu_dot+C(nu)nu+D(nu)nu+g(eta)=tau+tau_env` 出发；当前代码只保留三轴平移
   相对模型和一个独立 yaw 模型。
2. **数学模型有、代码省略**：没有实现 roll、pitch 的坐标旋转补偿；`z` 轴在 yaw
   旋转中保持不变。机体有明显横滚或俯仰时，代码不再等价于六自由度模型。
3. **数学模型有、代码省略**：没有显式计算刚体/附加质量产生的科氏和离心项
   `C(nu)nu`、恢复力 `g(eta)`、平移与姿态耦合项以及环境力 `tau_env`。
4. **严格不同**：代码要求平移模型和 yaw 模型使用相同固定 `dt`；参考对话允许 yaw
   内外环采用独立周期 `T_y`，PDF 也没有强制二者同频。
5. **代码额外加入**：所有 yaw 角在每步后折返到 `[-pi,pi)`；PDF 公式没有规定角度
   折返方式。
6. **已接入实机候选**：`live_integration_example.py` 从当前实验 JSON 读取相机旋转和
   CAD 光心杠杆臂；两者仍带参数文件中记录的标定风险，尚未解除正式控制禁用标志。
7. **数学模型有、代码省略**：相机、IMU 和控制量只由调用方声明为同一时刻，代码
   没有检查时间戳，也没有按照相机曝光时刻回放 IMU 历史姿态。
8. **数学模型有、代码省略**：没有显式补偿 IMU yaw/角速度零偏、相机延迟和控制
   通信延迟。
9. **仅符号不同**：数学推导统一用 `omega`，部分 Python 接口仍叫 `yaw_rate`，且保留
   兼容别名 `a_r/b_r`；内部物理量仍表示同一个 yaw 角速度。

## 3. 平移动力学与离散模型的差异

10. **仅实现形式不同**：PDF 先写潜器平移动力学 `M_t u_dot+h(u)=tau_t`，代码直接
    实现相对速度受潜器控制力反向作用的形式，因此离散输入矩阵 `G` 带负号。
11. **数学模型有、代码省略**：PDF 给出
    `H=D_L+2D_Q diag(|u_0|)`；代码固定使用 `H=D_L`，没有二次平移阻尼 `D_Q`，也
    不会随非零工作点 `u_0` 在线更新线性化矩阵。
12. **代码额外加入**：代码要求 `M_t` 对称正定、`D_L` 的对称部分半正定，并拒绝
    非有限参数；PDF 没有写这些软件输入检查。
13. **严格不同于基础平移包、但与旋转 PDF 对齐**：基础平移代码对位置使用精确 ZOH
    积分；旋转代码改为 PDF 的端点速度规则 `p+=Rp+Ts v+`。因此它不是连续平移方程
    在一个周期内的精确位置积分。
14. **已按滚动公式对齐**：每次求解的 `tau_base,k` 直接等于上一拍实际达到的力，并在
    本次完整 horizon 内固定；门控 EMA 和模型内可变 baseline 已删除。
15. **数学模型有、代码省略**：目标自身加速度、水流和未建模平移扰动没有单独状态或
    扰动观测器，只能由卡尔曼过程噪声和模型融合间接吸收。

## 4. yaw 动力学、状态机和预测的差异

16. **严格不同**：PDF 展示的线性 yaw 离散式是前向欧拉
    `omega+=(1-Ts*d/m)omega+(Ts/m)N`；代码对线性阻尼采用精确 ZOH：
    `a=exp(-d*Ts/m)`、`b=(1-a)/d`、`omega+=a*omega+b*N`。
17. **仅近似实现**：PDF 连续模型含 `d_omega2 |omega| omega`；代码支持该项，但在每个
    周期内把它冻结为常数后再用线性 ZOH 更新，而不是精确求解非线性微分方程。
18. **严格不同的默认值**：代码默认 `quadratic_damping=0`，所以示例实际运行的是线性
    yaw 模型；只有实测后显式填入非零值才包含二次阻尼。
19. **数学模型有、代码省略**：PDF yaw 方程包含外部扰动力矩 `d_N`，代码没有该输入，
    也没有 yaw 扰动观测器。
20. **代码额外加入**：代码使用 `HOLD/TURN/SETTLE` 三状态、触发连续帧和完成连续帧；
    PDF 只要求 yaw 状态机/独立姿态控制，没有完整规定这些软件状态。
21. **代码额外加入**：`alpha_on/alpha_off/alpha_emergency` 回差、可选向外运动判据、
    紧急更新 `psi2`、角度/角速度/视线三重完成条件，均来自参考对话和工程防抖设计。
22. **代码额外加入**：外环与内环积分限幅、条件抗饱和、`omega_command` 变化率限制、
    `N` 绝对值与变化率限制以及可选动力学前馈，PDF 没有逐条给出。
23. **严格不同**：未来 yaw 预测在当前状态机模式和目标角不变的前提下模拟 PID；预测
    时域内不会根据“未来目标视线角”再次触发模式切换或更新 `psi2`。
24. **实现边界**：`omega_command_max` 只限制期望角速度，不是对预测实际 `omega` 的硬
    约束；瞬态实际角速度仍可能超过该数值。
25. **实现边界**：当前周期规划使用预测 `N` 生成冻结 yaw 轨迹；历史评分则使用实际
    IMU yaw 增量。这符合“规划用名义值、回放用实际值”，但两条轨迹不会完全相同。
26. **代码额外加入**：`yaw_moment_base` 用于锁存/安全输出，没有作为 PDF 的 `d_N` 或
    平衡力矩进入正常 yaw 状态方程。

## 5. 双模型历史评价和融合权重的差异

27. **代码额外明确**：PDF 给出历史评价思想；当前实验平移融合使用窗口长度 8、预测
    区间 5、`H_cap=[5,5,5,5,5,4,3,1]` 和 `omega_h=[1,1,1,1,1]`，这是用户后续调整并
    由代码实现的更具体版本。
28. **代码额外加入**：除预测步权重外，代码还使用遗忘因子 `0.8` 对目标时刻较旧的
    格子降权；PDF 公式没有固定该数值。
29. **代码额外加入**：每轴位置残差先截断到 `[-0.5,0.5] m` 再计算矩；PDF 提到截断
    思路但没有给出这组三轴默认阈值。
30. **严格不同**：PDF 权重公式为
    `a1=clip((M2-C)/(M1+M2-2C+epsilon),0,1)`；代码为
    `a1=clip((M2-C+epsilon)/(M1+M2-2C+2epsilon),0.01,0.99)`，且候选模型
    不可区分时保持模型一偏好。
31. **严格不同**：因此即使统计量极端偏向某一模型，代码也不会给出 0 或 1 的纯模型
    权重；PDF 允许纯模型。
32. **严格不同**：没有任何启用格子时，代码保留上一次权重；初始化时使用
    `A1=diag(0.8,0.8,0.8)`。PDF 没有规定无样本时的值。
33. **术语差异**：代码中的 `C12` 是加权误差乘积二阶矩
    `sum(w*e1*e2)`，没有减去误差均值；如果 PDF 的“互协方差”按严格统计定义理解，
    二者不同。
34. **实现选择**：代码以卡尔曼滤波后的位置作为历史“实际位置”进行评分，不用原始
    相机位置，也没有真值；PDF 没有明确评分基准是否先滤波。
35. **实现次序**：当前测量先用旧融合权重完成滤波均值预测，再加入刚完成的历史格子
    更新权重，最后把新权重用于当前 QP。PDF 没有规定这一拍内的先后顺序。
36. **数学模型有、代码保持简化**：权重仍是三轴独立对角量，没有完整的跨轴模型误差
    协方差或非对角融合矩阵。

## 6. 卡尔曼滤波的差异

37. **代码具体化 PDF 未展开部分**：状态固定为 `[p_rel,v_rel]`，只测位置；初始速度
    默认 0，初始协方差、测量噪声和加速度过程噪声均为固定对角矩阵。
38. **数学模型有、代码省略**：没有根据视觉置信度、距离或检测框质量在线改变测量
    协方差，也没有创新门控和离群点拒绝。
39. **数学模型有、代码省略**：滤波器没有目标加速度、环境流速、模型偏差、相机偏置
    或 yaw 扰动状态。
40. **严格简化**：IMU yaw 增量被视为完全已知的确定旋转；IMU 角度不确定性没有进入
    状态协方差。
41. **严格简化**：双模型权重不确定性、yaw 模型参数不确定性和控制执行误差没有进入
    卡尔曼过程协方差。
42. **离散细节不完全一致**：过程噪声 `Q` 使用常见白加速度模型中的
    `0.5*Ts^2` 位置系数，而均值递推使用 `p+=Rp+Ts*v+`；二者并非同一端点速度离散规则
    的严格噪声离散化。
43. **实现边界**：没有缺测更新接口；视觉丢失时由 tracker 进入安全输出，而不是只做
    若干步卡尔曼预测。

## 7. MPC 代价、约束和数值求解的差异

44. **已按 PDF 对齐**：力代价始终是绝对总力 `tau_j' R_tau tau_j`；旧
    `effective-force` 代价和 `force_cost_mode` 开关已删除。变化率代价独立作用于
    `tau_j-tau_{j-1}`，第一步使用实际 `tau_achieved,k-1`。
45. **融合仿射项**：旋转动力学同时使用
    `-A1 R_j G tau_base,k -(I-A1) R_j G tau_h`，两份力在一次求解中都固定。
46. **参数化差异**：PDF 的 `Q_p,Q_v,P_p,P_v,R_tau,S_tau` 可为一般矩阵；代码只接受
    三个对角权重向量，不支持轴间交叉权重。
47. **严格限制**：代码强制 `P_p=terminal_weight_scale*Q_p`、
    `P_v=terminal_weight_scale*Q_v`；PDF 允许终端权重独立设置。
48. **代码额外加入**：每个预测步有 6 个松弛变量，代价同时含二次项、线性项，并有
    `slack_max`；PDF 只说明软约束，没有给出完全相同的松弛结构。
49. **代码额外加入**：除水平/垂直视场外，前向最近和最远距离也被软化；PDF 的核心
    软约束重点是视场，未规定这两个距离必须共用软约束。
50. **实现选择**：视场用固定半角减固定余量后的正切棱锥
    `|p_side| <= tan(theta-margin)*p_forward` 表示；PDF 没有固定完全相同的几何裕量方式。
51. **代码额外加入**：QP Hessian 加 `1e-9 I` 正则项以增强数值稳定性；数学代价中没有
    这一项。
52. **代码额外加入**：OSQP 的容差、最大迭代、`rho`、35 ms 时间限制、热启动平移和
    接受求解状态的规则属于求解器实现，不在数学模型中。
53. **代码额外加入**：QP 失败时，输出按力增量限制向“上次可行力”或固定 `tau_h` 移动；
    PDF 没有规定失败回退策略。
54. **诊断差异**：回退时返回的 slack 全部置 0，预测轨迹也只是用第一步回退增量重新
    计算；这些值不表示原失败 QP 的真实约束违反量。
55. **数学模型有、代码未加入**：没有终端不变集、显式稳定性约束或由 Riccati 方程求得
    的终端矩阵；PDF 虽未强制这些项，但一般 MPC 理论可能要求另行论证。
56. **实机已知可达域、冻结 yaw**：yaw 力矩不是 QP 决策量，但其预测序列作为每步已知量
    进入 `W_4x8 u_thr=[F_frd,N_yaw]`。八台推进器力按实机 M1..M8 顺序分别受正反向
    限额约束，因此平移与 yaw 共享已知四轴可达域并保留推进器零空间；未知 CG 和本地
    roll/pitch PID 用量没有被伪装成完整六轴模型。

## 8. 推进器、接口和实机执行方面的差异

57. **QP 已物理分配、旧接口仍保留**：`YawMPCResult.thruster_force_sequence` 是满足
    物理矩阵和逐台限额的分配结果；`FineSUBThrusterAllocator` 仍只是旧固件归一化
    混控接口，实机若发送八路电机应使用 QP 分配结果并做 N 到驱动命令的推力曲线转换。
58. **严格简化**：QP 平移约束已区分正反推力，但平移力/yaw 力矩到协议通道的 adapter
    仍采用线性比例；没有完整死区、流速影响、互扰和电压变化模型。
59. **实现边界**：标称电机饱和已在同一次 QP 中重新分配；未建模的死区、电压、互扰
    或执行故障仍会在后级形成额外饱和，必须通过实际达到的力/力矩反馈。
60. **实现边界**：tracker 要求调用方传入“上周期实际达到的力和 yaw 力矩”；如果实机
    只能回传命令而没有推力估计，历史融合将再次把命令当实际执行量，这与 PDF 的实际
    控制回放要求不同。
61. **数学模型有、代码省略**：roll/pitch 控制量既不进入相对位置预测，也不进入平移
    QP；安全实机入口当前也无法从下位机遥测取得未来 roll/pitch PID 用量。
62. **代码额外加入**：视觉丢失、未锁存基线、QP 失败等安全状态和返回格式是工程接口
    设计，PDF 没有规定。
63. **实现边界**：`live_integration_example.py` 自身不打开相机、串口、网络或推进器；
    完整安全实机状态机由 `MPC_dual_model.auto_only_runtime` 提供，并调用同一严格构造器。
64. **实现边界**：代码没有在线辨识或自适应更新 `M_t,D_L,m_omega,d_omega` 等动力学
    参数。

## 9. 结论

旋转后的核心预测结构、三输入 QP、冻结 yaw 轨迹和二维历史阶梯已经按数学模型实现。
目前最需要明确的“公式级差异”是：

1. yaw 线性模型使用精确 ZOH，而 PDF 展示前向欧拉；
2. 融合权重公式加入了不同的 `epsilon` 形式、不可区分判据和 `0.01--0.99` 保护范围。

其余差异主要是 roll/pitch 视觉旋转、滤波/驱动转换/时延仍为工程简化，以及状态机、
软约束和失败回退等代码额外安全策略。所有需要实测或实验选择的参数见
`CALIBRATION_CHECKLIST.md`。
